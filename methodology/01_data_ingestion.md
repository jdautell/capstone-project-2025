# Step 1 — Data Ingestion and LUAD Filtering

> Maps to **§ 2.1–2.2** of [`docs/Capstone_Paper.pdf`](../docs/Capstone_Paper.pdf).

## 1.1 Source datasets (GDSC bulk download)

All five raw files are pulled from the **Genomics of Drug Sensitivity in Cancer
(GDSC)** project bulk-download portal:

🔗 https://www.cancerrxgene.org/downloads/bulk_download

| File                                | Purpose                                                                       |
|-------------------------------------|-------------------------------------------------------------------------------|
| `GDSC2_fitted_dose_response_27Oct23` | Target variable — `LN_IC50` per (cell line × drug)                            |
| `Cell_Lines_Details`                 | Tissue type, growth conditions, COSMIC ID metadata                            |
| `Cell_line_RMA_proc_basalExp`        | RMA-normalized gene expression matrix (wide format, COSMIC IDs as columns)    |
| `mutations_all_20230202`             | Binary somatic mutation table on cancer driver genes (indexed by `model_id`)  |
| `screened_compounds_rel_8.5`         | Drug name, target, and pathway metadata                                       |

GDSC was generated by exposing ~1,000 human cancer cell lines to hundreds of
anti-cancer compounds and recording dose-response curves via high-throughput
screening (Iorio et al., 2016).

## 1.2 LUAD restriction

LUAD is the most common subtype of non-small cell lung cancer (NSCLC) and the
focus of this capstone. The cell-line panel is restricted to LUAD samples via
the `Cell_Lines_Details.tissue` column:

```
LUAD_mask        = Cell_Lines_Details["Cancer Type (matching TCGA label)"] == "LUAD"
luad_cosmic_ids  = Cell_Lines_Details.loc[LUAD_mask, "COSMIC identifier"].unique()
```

All downstream merges retain only rows whose `COSMIC_ID` is in `luad_cosmic_ids`.

## 1.3 Reshape `Cell_line_RMA_proc_basalExp`

The RMA expression matrix is delivered in **wide format** (genes × cell lines,
with COSMIC IDs as column headers). It is transposed so that **rows = LUAD cell
lines, columns = genes** — the canonical orientation for downstream merging:

```
expr_luad = (
    Cell_line_RMA_proc_basalExp
    .set_index("GENE_SYMBOLS")
    .T                                       # cell-line rows
    .reset_index()
    .rename(columns={"index": "COSMIC_ID"})
    .pipe(lambda df: df[df["COSMIC_ID"].astype(str).isin(luad_cosmic_ids.astype(str))])
)
```

## 1.4 Merging key — COSMIC ID + DRUG_ID

The dose-response, expression, and drug-metadata tables are joined on the natural
keys:

| Join                                                      | Key             |
|-----------------------------------------------------------|-----------------|
| `expression × dose_response`                              | `COSMIC_ID`     |
| `dose_response × screened_compounds_rel_8.5`              | `DRUG_ID`       |
| `(above merged) × Cell_Lines_Details`                     | `COSMIC_ID`     |

## 1.5 Mutation merge — Sanger `model_id` mapping

The mutation file is indexed by **Sanger `model_id`**, not COSMIC ID. A
two-step join is required:

1. Filter mutation rows to those flagged as **cancer drivers**.
2. Reshape long → wide so each LUAD cell line has one row, with binary columns
   per driver gene (`1` = mutation present, `0` = wild-type).
3. Map `model_id → COSMIC_ID` via the auxiliary identifier table provided by
   GDSC, then inner-join on `COSMIC_ID`.

```
mut_drivers = (
    mutations_all_20230202
    .query("cancer_driver == True")
    .assign(present=1)
    .pivot_table(index="model_id", columns="gene_symbol",
                 values="present", fill_value=0)
)
mut_drivers = mut_drivers.join(model_to_cosmic).set_index("COSMIC_ID")
```

## 1.6 Resulting multi-omic table

After the full merge, each row is one **(LUAD cell line × drug)** observation with:

- **Target:** `LN_IC50` (continuous, log-transformed dose-response).
- **Continuous features:** gene-expression values for the full GDSC gene panel.
- **Binary features:** driver-mutation status (one column per driver gene).
- **Categorical features:** drug name, drug target, target pathway, growth
  conditions (one-hot encoded in step 2).

The resulting wide dataset carries roughly **17,000 numerical features** and is
the input to all preprocessing, EDA, and modeling stages.
